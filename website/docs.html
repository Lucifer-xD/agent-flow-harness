Install

  1. Download the installer for Windows 10 or 11 (64-bit), or for a Mac. Prefer a terminal, or on Linux? Install the terminal app instead.
  2. Run it. If Windows says it protected your PC, choose More info → Run anyway — AFH is new, so SmartScreen doesn't know it yet.
  3. AFH opens when it's installed. Next time, find it in the Start menu.

On a Mac: open the DMG and drag AFH to Applications. The app isn't signed by Apple yet, so the first time, macOS won't open it. Go to System Settings → Privacy & Security and choose Open Anyway. You only do this once. If macOS says the app is damaged, run xattr -dr com.apple.quarantine "/Applications/Agent Flow Harness.app" in Terminal.

On Windows, AFH updates itself: new versions download in the background and install when you restart it. See Updates.

Connect a model

Open Settings → Models & providers. There are four ways in — use as many as you like.

Sign inChatGPT uses your Plus, Pro or Team plan — no API key. GitHub Copilot gives you a code to enter on GitHub. OpenRouter creates a key for you.
Add a providerSearch the catalogue of 228 providers, pick one and paste its API key. Keys are stored only on this computer.
Models on this computerRunning Ollama, LM Studio, vLLM, llama.cpp or Jan? AFH finds them — no key needed.

ChatGPT (chat): the real GPT-6 family

Besides the Codex sign-in, Settings → Models → ChatGPT (chat) connects the models you talk to on chatgpt.com — GPT-6 Astra, GPT-6.1 Sol, GPT-5.6 Terra and the rest of the family — and lets them drive the whole harness as agents. Usage is drawn from your ChatGPT plan, not from Codex credits.

  1. Sign in to chatgpt.com in your browser as usual.
  2. In AFH choose ChatGPT (chat) → Import from browser, which copies the session from the browser you pick — or open https://chatgpt.com/api/auth/session in that browser and paste the JSON it shows into the box.
  3. Pick a GPT-6 model in the message box. Every reply carries a green real model badge naming the model that actually answered, so you can tell it apart from a fallback.

The session stays on this computer like any other key. When it expires, import it again — nothing else changes.

Custom endpoint

For any other server, choose Custom endpoint and fill in the API format (OpenAI-compatible, Anthropic or Gemini), a Base URL, an API key if it needs one, and the Model ids.

Claude Pro/Max plans can't be used by sign-in in other apps — use an Anthropic API key instead.

Your first thread

  1. Click New thread (Ctrl N) and choose the project folder to work in.
  2. Pick a model in the message box, and a mode — Build is the default.
  3. Say what you want, like you'd tell a teammate: "Add a login page with email and password, and make sure the tests pass."
  4. Press Enter. The agent sets a goal, makes a to-do list and starts working. Watch files appear in the Live pane.
  5. Press Esc any time to stop it.

Paste or drop screenshots and files into the message box, or press the mic and speak.

Modes

ModeWhat it does

DelegateLeads the work and hands tasks to your delegate models.
Red TeamAudits your own project for exploitable weaknesses — auth and OTP flaws, privilege escalation, injection, exposed secrets — and reports each with its severity, how it is exploited and the fix. Never edits code.

Create your own agents — with their own prompt, model and tools — from Create or edit agents… at the bottom of the mode menu. Each can be a main mode, a subagent, or both, and can be made read-only.

Goals & to-dos

For anything bigger than a quick fix, the agent writes a goal — what "done" means — and a to-do list. Both sit right above the message box.

  • Add, reorder or tick to-do items yourself; the agent sees your changes on its next turn.
  • Set a goal yourself with /goal, or edit the list with /todo.
  • When a choice is yours, the agent pauses and asks you multiple-choice questions.
  • Achieved goals and finished lists are kept in the Goal button's menu.

Project memory

The agent keeps a short list of what it has learned about each project — how to install, run and test it, the conventions, the gotchas, how you want things done — and every new thread there starts by reading it. It's a plain file, .afh/memory.md, inside your project.

  • Open Memory beside the Goal button (in the message box before a thread starts) to see everything it knows. Add a line, click one to edit it, or forget it; Edit as text opens the whole file.
  • Tell it in the chat — “remember that the API runs on port 4000” — or type /remember and the fact. /memory opens the list.
  • The agent saves on its own when it works something out or you correct it, and fixes facts that turn out wrong. Its changes show up live, marked new.
  • Lines that start with “- ” are facts; anything else you write in the file is a note the agent reads too.
  • It's private: the file stays on your computer, and AFH keeps it out of git, so access tokens and logins are fine to keep there for the agent to use. Like everything the agent reads, it is sent to your model provider as part of the prompt.
  • Your changes reach the agent on its very next step — even in the middle of a run.

Helpers

The lead agent can hand self-contained tasks to helpers that run in parallel. The built-in Helper is a copy of your own model; set up more delegate models in Settings → Delegation. Watch any helper from the top bar: what it was asked and what it sent back.

Live pane & undo

Open Live in the header to watch each file as it's written, character by character.

Don't like where a turn went? Hover your message and choose Undo to here. The thread and the files on disk go back to just before that message, and your message returns to the box so you can change it and send again. Choose Put it back if you change your mind. Fork thread from here starts a copy instead.

Built-in browser & DevTools

The agent has a browser tool that drives a real browser in the Browser tab of the workbench, next to Live and Changes. You watch what it does as it happens — open your dev server, click through a flow, read the errors — and you can take over the page yourself at any time.

ActionWhat it does
openLoads a URL in the panel.
screenshotSends the model a picture of the page.
textReads the page as text — cheaper and more exact than a screenshot.
click, type, press, scrollClicks an element, types into a field, presses a key, scrolls.
evaluateRuns JavaScript in the page, as if typed into the console, and returns the result.
consoleThe page's console: log messages, warnings and errors since it loaded.
networkEvery request the page made, with status, type, size and timing. Add url=<part> to get one request's headers and response body.
sourcesThe files the page loaded — scripts, styles, data. Add url=<part> to read one.

So when a page breaks, the agent can do what you would: check the console, find the request that answered 500, read its response, open the source file that sent it and fix the code. Ask for it directly — "open localhost:3000, try the login form and tell me why it fails" — or let it reach for the browser on its own when it is testing something it built.

The browser is a separate profile inside AFH: sign-ins you make there stay there, and nothing from your everyday browser is shared with it.

Set the default in Settings → General → Default approval mode. When it asks, you can allow an action always for that thread. Reading .env files always asks, whatever the mode.

Worktrees

Turn on Work in a separate git worktree when starting a thread and it gets its own branch and folder. When you're happy, open the Worktree menu and choose Merge into your base branch — or remove it. Your main checkout is never touched. Needs Git.

Terminal

All of AFH, full screen in any terminal, over SSH or in a script. You don't need the desktop app. Install it with one command:

Then go to a project folder and type afh. Type / for commands, @ for files, ! to run a shell command and ? for help. /connect adds a provider. See the Terminal page for every key.

Already have the desktop app? Settings → Developer → Command line → Install puts the same afh on your PATH. The two share threads, settings and keys, and afh connects to the app when it's open.

afh update installs the newest version. afh uninstall removes the program and keeps your threads, settings and keys. afh --plain gives a simple line chat for basic terminals.

afh                                  # chat in this folder
afh run "fix the failing tests"      # one task, then exit
git diff | afh run "review this" -q > review.md

When the app is open, afh uses it, so threads show up there live. When it isn't, afh starts a private backend for as long as the command runs.

Every flag and exit code is in the command line guide.

GitHub agent

Write /afh and what to do at the start of a line in a comment on an issue or pull request. AFH does the work on your computer, then opens a draft pull request or pushes to the pull request.

It needs the GitHub CLI signed in, a local clone, and the app or afh serve running. Turn it on in Settings → GitHub, or from a terminal:

afh github add owner/repo --path ~/code/repo
afh github allow your-login a-teammate
afh github mode ask

A comment can end up running code on your computer, so AFH is careful with it:

  • Only logins you allow can start work. By default that's just you.
  • The words after /afh are the instruction. The issue's own text reaches the model as untrusted content.
  • Pull requests from forks are refused.
  • It pushes only an afh/... branch or the pull request's own branch. It never force-pushes and never merges.
  • In ask mode, the default, edits and commands wait for your approval in the app or on your phone.

full mode runs without asking, so an issue's text could steer it. Use it only on repositories you trust.

Model races

Give one task to several models. Each works in its own git worktree, your --check command scores each result, and you pick which one to merge. Races run from the command line.

afh race "add caching to the API" -m openai/gpt-5 -m anthropic/claude-opus-5-5 --check "pytest -q"
afh race show <id>
afh race pick <id> <number>
afh race discard <id>

The models run with Full access unless you pass --mode. A worktree holds only what's committed, so a check may need to install things first, like npm ci && npm test.

Commands & skills

Type / in the message box for commands. Built in: /goal, /todo, /memory, /remember, /compact, /jobs, /new, /cost, plus /review, /fix-tests, /explain and /commit.

Add your own in Settings → Commands, or as Markdown files in ~/.afh/commands, .afh/commands or .claude/commands in your project. Use $ARGUMENTS or $1…$9 for what you type after the command.

Skills and MCP servers

Skills are folders with a SKILL.md in ~/.afh/skills or your project's .afh/skills — folders made for other agents (.claude/skills, .agents/skills) work too. Add MCP servers in Settings → MCP servers → Add server, as Local (stdio) or Remote (HTTP).

Or just ask: the agent can install skills, MCP servers, commands, hooks and agents itself.

Hooks

Hooks run your own commands at three moments: pre_tool (before a tool), post_tool (after it) and stop (when the agent finishes). Set them up in Settings → Hooks.

  • Exit with code 2 from pre_tool to block that tool call.
  • Exit with code 2 from stop to make the agent keep going (up to 3 times a run).
  • Hooks get AFH_EVENT, AFH_TOOL, AFH_TOOL_INPUT, AFH_FILES, AFH_SESSION_ID and AFH_PROJECT_DIR.

Themes & language

Settings → Appearance has 46 themes (29 dark, 17 light) and a Custom option, plus how the switch looks: Circle, Diamond, Wipe, Fade, Blur or None. The sun/moon button in the header flips between your favourite light and dark themes.

From your phone

The AFH app for Android and iPhone (download) has two sides. Chats talks to model providers straight from the phone with your own API keys (add them under Settings → Providers; they stay in the phone's secure storage). Computers follows and steers AFH on your computer from anywhere: your threads streaming live, approvals and questions, and a message box to send the next task or stop a run.

  • On the computer, click Sign in at the bottom of the sidebar (the account button, next to the settings, language and theme buttons). Your browser opens agentflowharness.com/account: sign in or create the account there and approve the computer (check the code matches). AFH never sees your password. Turn Reachable from your phone off to hide the computer again.
  • In the app, open the Computers tab and sign in with the same account. Computers are listed with who's online; tap one for its recent threads across projects, tap a thread to follow it, or use New thread to start one in any of its projects.
  • The account is only for remote access; AFH itself needs none. The server keeps your email, a hash of your password and your list of computers — never threads, files or keys. Traffic goes over HTTPS through agentflowharness.com.
  • Anyone signed in to the account can use AFH on your computers like you, including running commands. Use a strong password; changing it signs out every phone. Rename or remove computers, change the password or delete the account on your account page.
  • Who can reach the computer is decided only on the computer: remote access settings can't be changed from the phone.
  • On the same Wi-Fi you can also use the password-protected address under On your own network, no account involved.

Updates

AFH checks this website for new versions and downloads them in the background. When one is ready you'll see Restart to update; otherwise it installs the next time you quit.

In Settings → About → Updates you can Check now, turn off Download updates automatically, or set a different Update address.

Your data

Everything stays on your computer, in %USERPROFILE%\.afh. Nothing is sent anywhere except to the model providers you set up — plus the update check, the daily model-catalogue refresh, and web search or voice if you turn them on. The app sends no telemetry. The website's server log counts downloads, visits and apps in use (from update checks and phone sign-ins) as daily totals, and that never includes your code or chats.

Getting help

Something wrong? Settings → Report a bug → Create report saves a zip to your Downloads folder with the logs and your setup — keys masked, and sent nowhere. Share it with whoever is helping you.

FAQ

Is AFH free?

Yes, with no account needed. You pay your model provider as usual — or nothing extra with a ChatGPT or Copilot plan you already have, or local models.

Can I use it offline?

With a model running on your PC (Ollama, LM Studio and so on), yes.

Can I bring my OpenCode or Zadloop threads?

Yes. Settings → Models & providers offers a one-time Import from OpenCode (keys, endpoints, MCP servers and threads). For single threads, open the palette and choose Import thread….

Mac or Linux?

The desktop app runs on Windows and Mac. The terminal app also runs on 64-bit Linux. Computer use is Windows only.

Is there a command line?

Yes: afh opens AFH full screen in your terminal, and afh run does one task from a script. No desktop app needed. See Terminal.
