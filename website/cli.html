Terminal

All of AFH.
In your terminal.

The same agent as the desktop app, full screen in any terminal. Threads, models, approvals, goals, helpers, every setting. It runs on its own: no desktop app needed.

Then go to a project folder and type afh. Windows, Mac and 64-bit Linux. No admin rights needed.

Its own design

A terminal app that looks like AFH.

The mark from the app, drawn in your terminal, flowing while it works. The conversation runs down a strand, every step a point on it, and joins the message box. During a run, light travels along it.

The same AFH

Not a smaller version.

It talks to the same engine as the desktop app, and shares its threads, settings, providers and keys. If the app is open, the terminal connects to it, and you can watch the same thread in both.

Questions

Good to know.

Which terminals work?

Windows Terminal, the terminal in VS Code, macOS Terminal, iTerm2 and modern Linux terminals. The old Windows console window works but shows fewer colors. In a very basic terminal or a pipe, afh uses a simple line chat.

What can't a terminal do?

It can't draw images or embed a browser, so screenshots and design previews open in your own viewer and browser. The mic is in the desktop and phone apps. The rest is here.

Why does my antivirus question it?

AFH isn't code-signed yet, so some antivirus programs are wary of new builds. The installer checks the SHA-256 of every download against the release.

Can I read the script first?

Yes: install.ps1 and install.sh. They download a release from GitHub, check it, unpack it to the .afh folder in your home folder and add afh to your PATH. Nothing needs admin rights.
