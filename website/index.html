How it works

Say it. Watch it build.

01

Say what you want.

Type it like you'd tell a teammate. No setup, no special commands — AFH reads your project and gets moving.

02

It sets a goal and makes a plan.

The agent writes down what "done" means, then breaks the work into a to-do list you can watch tick off — and edit any time.

03

It does the work — and splits it.

Reads, edits, runs and tests, each step a card in the thread. A lead can hand pieces to helpers that run side by side, each in its own lane or git worktree.

04

You watch every line land.

The Workbench shows the file being written, the diff of everything changed, and the browser the agent drives. Don't like a turn? Rewind the thread and the files.

Four ways to work

Pick the mode. The harness does the rest.

Ship it.

Reads, edits, runs and tests. Asks before anything risky — or runs on its own when you say so. Every change is a card you can open, and undo.

edit src/pages/login.tsx +84 −3
shell npm test 12 passed
browser open localhost:3000/login
goal achieved · login works

Think first.

Reads everything, writes nothing. You get a plan with the files it will touch before a line changes — then switch to Build and let it go.

read src/auth/*.ts · 6 files
plan 1. session cookie 2. form 3. tests
no edits in Plan mode

Fan out.

A lead model briefs helpers that work at the same time, each in its own lane or worktree, and checks what they bring back.

delegate Helper → "write the tests" running
delegate Helper → "style the form" running
merge branch afh/helper-tests clean

Break it before they do.

Audits your own project for exploitable weaknesses — auth and OTP flaws, privilege escalation, injection, exposed secrets — and reports each with severity, exploit and fix. Never edits code.

critical OTP accepts any 6 digits after 3 tries
high admin role set from request body
medium API key in client bundle

Terminal · GitHub · Races

The agent, wherever you work.

Run it from a terminal, hand it an issue, or give one task to several models and keep the best result.

In your terminal

All of AFH, full screen: threads, models, approvals and every setting. Or one task from a script with afh run.

On GitHub

Write /afh and a task on an issue. AFH does the work on your computer and opens a draft pull request.

you /afh fix the login redirect
afh on its own branch running
draft PR ready to review #42

Model races

afh race gives one task to several models, each in its own worktree. Your tests score them, and you merge the one you pick.

model 1 tests 12 passed
model 2 2 tests failed
pick 1 merged into main
