How it works

01

Say what you want.

Type it like you'd tell a teammate. No setup, no special commands — AFH reads your project and gets moving.

02

It sets a goal and makes a plan.

The agent writes down what "done" means, then breaks the work into a to-do list you can watch tick off — and edit any time.

03

It splits the work across agents.

A lead agent hands pieces to helpers that run side by side — each in its own lane, even its own git worktree — and checks what they bring back.

Four ways to work

Pick the mode. The harness does the rest.

Build

Ship it.

Reads, edits, runs and tests. Asks before anything risky, or runs on its own when you say so.

Plan

Think first.

Reads everything, writes nothing. You get a plan with the files it will touch before a line changes.

Delegate

Fan out.

A lead model briefs helpers that work at the same time, each in its own lane or worktree.

Red Team

Break it before they do.

Audits your own project for exploitable weaknesses — auth and OTP flaws, privilege escalation, injection, exposed secrets — and reports each with severity, exploit and fix. Never edits code.
