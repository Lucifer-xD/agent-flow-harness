How a turn works

Say it. Watch it build.
Read the answer.

  1. 01

    Say what you want.

    Type it like you'd tell a teammate. AFH reads your project and gets moving — no setup, no special commands.

  2. 02

    It sets a goal and makes a plan.

    The agent writes down what "done" means and breaks the work into a to-do list you can watch tick off — and edit any time.

  3. 03

    It does the work — and folds it away.

    Reads, edits, runs and tests. While it works you see every step; when it's done they fold under one line, so the answer stays in front.

    Read src/auth/session.ts
    Edited login.tsx +84 −3
    Terminal4.2sexit 0
    $ npm test

✓ login › redirects home (12 ms)
Tests: 12 passed, 12 total

    Login now keeps you signed in and sends you back to the page you came from. All 12 tests pass.

  4. 04

    You review every line.

    Every changed file is listed at the end of the reply. The workbench shows the diff, the file being written and the browser the agent drives. Don't like a turn? Rewind the thread and the files.

Four ways to work

Pick the mode. The harness does the rest.

Ship it.

Reads, edits, runs and tests. Asks before anything risky — or runs on its own when you say so. Every change is a card you can open, and undo.

edit src/pages/login.tsx +84 −3
shell npm test 12 passed
browser open localhost:3000/login
goal achieved · login works

Think first.

Reads everything, writes nothing. You get a plan with the files it will touch before a line changes — then switch to Build and let it go.

read src/auth/*.ts · 6 files
plan 1. session cookie 2. form 3. tests
no edits in Plan mode

Fan out.

A lead model briefs helpers that work at the same time, each in its own lane or git worktree, and checks what they bring back.

delegate Helper → "write the tests" running
delegate Helper → "style the form" running
merge branch afh/helper-tests clean

Break it before they do.

Audits your own project for exploitable weaknesses — auth flaws, privilege escalation, injection, exposed secrets — and reports each with severity, exploit and fix. Never edits code.

critical OTP accepts any 6 digits after 3 tries
high admin role set from request body
medium API key in client bundle
